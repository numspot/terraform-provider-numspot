# Acceptance Tests

Acceptance tests use the VCR system (go-vcr) to record and replay API calls.

## Prerequisites

Set the following environment variables:

```sh
export NUMSPOT_CLIENT_ID=<your_client_id>
export NUMSPOT_CLIENT_SECRET=<your_client_secret>
export NUMSPOT_SPACE_ID=<your_space_id>
export NUMSPOT_REGION=<your_region>  # e.g.: eu-west-2
export NUMSPOT_HOST_OS=<your_os_host> # e.g.: https://objectstorage.eu-west-2.numspot.com
export NUMSPOT_HOST=<your_iaas_host> # e.g.: https://api.eu-west-2.numspot.com
```

## Running Tests

```sh
# Run all tests with a specific VCR mode
VCR_MODE=replay make testacc

# Run a specific test
VCR_MODE=replay make testacc TESTARGS="-run TestAccVpcResource"

# Run in parallel
PARALLEL_TEST=true VCR_MODE=replay make testacc
```

## Workflow

- **Merge requests**: run the tests locally — in `replay` mode the cassettes
  are used and no real API calls are made, so the real credentials are not
  required (any non-empty values work).
- **CI**: the `acc-tests` job runs manually on the default branch only
  (typically before cutting a release tag). This keeps the CI/CD variables
  protected: they are only injected on protected branches.
- **New/changed cassettes**: re-record locally with `VCR_MODE=record` using
  real credentials (this creates and destroys real resources). Cassettes
  recorded with any space/organisation can be replayed with any other:
  space/organisation UUIDs are normalized by the matcher.

## VCR Modes

| Mode          | Description                           |
| ------------- | ------------------------------------- |
| `replay`      | Use recorded cassettes (no API calls) |
| `record`      | Make API calls and record cassettes   |
| `passthrough` | Real API calls without recording      |

## Server Certificate Tests

Some tests require a server certificate. Generate a self-signed certificate:

```sh
cd secrets
openssl req -x509 -newkey rsa:4096 -keyout server-key.pem -out server-cert.pem -days 365 -nodes -subj "/CN=server-certificate-acctest"
```

Export the certificate and private key as environment variables:

```sh
export SERVER_CERTIFICATE_ACCTEST="$(cat secrets/server-cert.pem)"
export SERVER_PRIVATE_KEY_ACCTEST="$(cat secrets/server-key.pem)"
```

**Note:** The certificate and private key environment variables are only required when running tests in `record` VCR mode. In `replay` mode, the recorded cassettes are used and no real API calls are made.

## Keypair Tests

Generate an SSH key pair for testing:

```sh
cd secrets
ssh-keygen -t ed25519 -f keypair-test -N "" -C "keypair-acctest"
```

Export the public key as environment variable:

```sh
export KEYPAIR_PUBLIC_KEY_ACCTEST="$(cat secrets/keypair-test.pub)"
```

**Note:** The keypair public key environment variable is only required when running tests in `record` VCR mode. In `replay` mode, the recorded cassettes are used and no real API calls are made.

The private key will be auto-generated by the API when creating a keypair without a public key.

## Cassettes

Cassettes are stored in `internal/test/testdata/*.cassette.yaml`.
