# Adding a Feature

This document describes the current workflow for adding a new Terraform resource or data source to `terraform-provider-numspot`.

> For a short, tool-agnostic orientation (commands, conventions, the `helpers.go` pattern), see [AGENTS.md](../../AGENTS.md).

## Pipeline Overview

Three tools chain together to produce a complete feature. Each tool has a single responsibility:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  1. tfplugingen-openapi  (+ cmd/inject-ignores pre, cmd/inject-schema-overrides post) │
│     Input:  OAS (public-oas.yaml) + spec YAML (filter) + descriptor.yaml    │
│     Output: JSON spec (IR)                                                  │
│     Role:   Select which OAS endpoints map to TF resource/datasource;       │
│             inject-ignores adds scope-param ignores to the spec YAML first,  │
│             inject-schema-overrides re-applies descriptor plan modifiers,     │
│             validators and defaults to the IR after (all survive regen)       │
├─────────────────────────────────────────────────────────────────────────────┤
│  2. tfplugingen-framework generate                                          │
│     Input:  JSON spec                                                       │
│     Output: _gen.go files (schema + models + custom types)                  │
│     Role:   Generate the TF schema, model structs, ObjectTypable/Valuable   │
│     Marked:  DO NOT EDIT                                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│  3. cmd/scaffold (our generator)                                            │
│     Input:  descriptor.yaml                                                 │
│     Output: core/<name>.go, resource_<name>.go, datasource_<name>s.go       │
│     Role:   Generate business logic (CRUD, serialize, deserialize)          │
│     Also:   Auto-maps SDK/TF fields; auto-patches provider.go               │
│     Marked:  Editable — residual TODOs for unmappable fields                │
└─────────────────────────────────────────────────────────────────────────────┘
```

Throughout these docs, **IR** (Intermediate Representation) means the generated
`*_spec.json` — the `terraform-plugin-codegen-spec` document that sits between the
sources (OAS + `*_spec.yaml` + descriptor) and the final `*_gen.go`.

> **Toolchain note.** `tfplugingen-openapi`, `tfplugingen-framework` and `oapi-codegen`
> are tech-preview / effectively unmaintained. They are pinned to exact versions in the
> `GNUmakefile` (`@v0.3.0` / `@v0.4.1` / `@v2.5.1`) so generation stays reproducible — never
> change them to `@latest`.

Files each tool produces:

```
internal/services/<name>/
├── <name>_spec.yaml                 ← you write (step 3)
├── <name>_spec.json                 ← tool 1 generates (step 4)
├── descriptor.yaml                  ← you write (step 2)
├── resource_<name>/                 ← tool 2 generates (step 4)
│   └── <name>_resource_gen.go          schema + KeypairModel
├── datasource_<name>/               ← tool 2 generates (step 4)
│   └── <name>_data_source_gen.go       schema + KeypairModel + ItemsValue
├── resource_<name>.go               ← tool 3 generates (step 5)
└── datasource_<name>s.go            ← tool 3 generates (step 5)

internal/core/
└── <name>.go                        ← tool 3 generates (step 5)

internal/provider/
└── provider.go                      ← tool 3 auto-patches (step 5)
```

---

## Architecture Layers

```
Terraform Config (.tf)
    ↓
resource_<name>.go          ← CRUD orchestration (uses _gen.go models + core functions)
    ↓
core/<name>.go              ← API calls (uses sdk/api client)
    ↓
sdk/api/numspot-client.go   ← auto-generated by oapi-codegen from OAS
    ↓
Numspot API
```

The `_gen.go` files sit beside the resource/datasource files — they define **what** the TF schema looks like, while the resource/datasource files define **how** it behaves.

## Step-by-step Workflow

### Step 1 — Initialize

```bash
make scaffold-init RESOURCE_NAME=organisation_role
```

Creates `internal/services/organisation_role/` with two template files:

- `descriptor.yaml` — scaffold configuration (you edit next)
- `<name>_spec.yaml` — OAS endpoint filter (you edit in step 3)

### Step 2 — Edit descriptor.yaml

```yaml
name:
  organisation_role # TF resource name (snake_case). The Go package folder is
  # ALWAYS derived from this (underscores removed): organisationrole
go_name: OrganisationRole # PascalCase Go identifier (constructors, core function prefix)
singular:
  OrganisationRole # TF model prefix (<Singular>Model) + SDK type lookup (matched
  # case/separator-insensitively, so "VMs"/"Vms" both find api.Vms)
plural: OrganisationRoles # TF plural + SDK plural lookup (ReadOrganisationRolesParams)
sdk_singular: "" # Optional: only for genuine name differences (e.g. DhcpOptionsSet) or
sdk_plural: "" # to disambiguate an ambiguous normalized match; NOT for casing
scope: organisation # space | organisation
has_tags: false # resource supports tags
is_async: false # resource has async states (pending → available)
has_update: false # resource has Update beyond tags
create_direct: true # Create returns JSON201 directly (no RetryRead after)
create_response_type: "" # Optional: SDK type returned by Create when different from Singular
has_resource: true # generate resource + core Create/Read/Delete
has_datasource: true # generate datasource + core ReadList
scaffold_check: false # when true, drift check enforces generated files match descriptor
reason: "" # Required when scaffold_check is false: why the resource is not fully generated
```

#### Flag reference

The Go package folder is **always** the concatenated lowercase form of `name` (underscores removed),
e.g. `dhcp_options` → `dhcpoptions`, `kubernetes_cluster` → `kubernetescluster`. There is no `package`
field; `cmd/scaffold audit` fails if a folder does not match this convention or if a stray `package`
override is present.

| Flag                          | Default               | `true`                                                                                                                                                                                                                | `false` / empty                                       |
| ----------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `sdk_singular` / `sdk_plural` | `singular` / `plural` | SDK type name override (used for `api.<X>`). SDK lookups are case/separator-insensitive, so this is only needed for genuine name differences (e.g. `DhcpOptionsSet`) or to disambiguate an ambiguous normalized match | Derive from `singular` / `plural`                     |
| `has_tags`                    | `false`               | Tags in serialize/mappingItemsValue, `<GoName>Tags()` helper, `Update<Resource>Tags()` in core                                                                                                                        | No tags                                               |
| `is_async`                    | `false`               | `pendingStates`/`targetStates`, `RetryRead<Resource>()`, Create polls until ready                                                                                                                                     | Sync: POST → JSON201 or POST → GET                    |
| `has_update`                  | `false`               | `Update()` with tags diff + TODO for custom logic                                                                                                                                                                     | Empty `Update()`                                      |
| `create_direct`               | `true`                | Create returns `JSON201` directly                                                                                                                                                                                     | Create calls `RetryRead` after POST                   |
| `scope`                       | `space`               | `provider.SpaceID`                                                                                                                                                                                                    | `provider.OrganisationID`                             |
| `has_resource`                | `true`                | Generates `resource_<name>.go` + `core/<name>.go` CRUD                                                                                                                                                                | Data-source only                                      |
| `has_datasource`              | `true`                | Generates `datasource_<name>s.go` + `core/<name>.go` ReadList                                                                                                                                                         | Resource only                                         |
| `scaffold_check`              | `false`               | `cmd/scaffold drift` enforces generated files match descriptor **and** `cmd/scaffold audit` fails on any residual `TODO` (full auto-mapping required)                                                                 | Allowed, but `cmd/scaffold audit` requires a `reason` |
| `reason`                      | `""`                  | —                                                                                                                                                                                                                     | Required when `scaffold_check` is not `true`          |

#### Common flag combinations

| Profile               | `has_tags` | `is_async` | `has_update` | `create_direct` | Example                          |
| --------------------- | ---------- | ---------- | ------------ | --------------- | -------------------------------- |
| IAM sync              | false      | false      | false        | true            | Role, Permission, ServiceAccount |
| Compute sync, no tags | false      | false      | false        | true            | Keypair                          |
| Compute sync, tags    | true       | false      | true         | true            | (rare)                           |
| Compute async, tags   | true       | true       | true         | false           | VPC, Subnet, Volume              |
| Data-source only      | false      | false      | false        | true            | Organisations                    |

For data-source only: set `has_resource: false`, `has_datasource: true`.

#### Pattern flags (preferred)

Prefer these high-level flags to describe how the TF model maps to the SDK. They keep the descriptor readable and are validated by `cmd/scaffold audit`.

```yaml
id_source: Name # TF "id" is stored in SDK "Name" (replaces Id -> Name overrides)
preserve_from_state: # Fields not returned by the API but kept in TF state
  - PrivateKey
exclude_from_request: # Fields not sent in the create/update request body
  - Fingerprint
  - Type
computed_fields: # Fields returned by the API but not provided by the user
  - Fingerprint
  - Type
managed_by_other_resource: # Fields managed by a dedicated TF resource (e.g. security group rules)
  - InboundRules
  - OutboundRules
null_on_read: # Nested leaves present in the TF schema but absent
  - block_device_mappings.bsu.iops #   from the *read* SDK struct (dotted snake_case)
  - block_device_mappings.bsu.volume_size
```

Rules:

- `id_source` replaces per-kind `Id -> Name` overrides.
- `preserve_from_state` skips the field when serializing read/create responses.
- `exclude_from_request` (and `computed_fields`) skips the field when building the create/update request.
- `managed_by_other_resource` behaves like `exclude_from_request` and is also checked by drift.
- `null_on_read` is for "superset" TF nested types: when a nested leaf exists in
  the schema but not in the read SDK struct (e.g. a write-only `iops` the read
  payload never echoes), the read serializer emits a typed null and the read
  deserializer skips it — instead of a TODO. Paths are dotted snake_case tfsdk
  tags descending nested objects. The create/update body must be mapped
  separately (usually a `deserialize` override) since the read serializer can't.

#### Mapping overrides (escape hatch)

When a field mapping is too specific for the pattern flags above, use `mapping_overrides`. Each override must include a `reason`; otherwise `cmd/scaffold audit` fails.

```yaml
mapping_overrides:
  serialize: # read response: TF model -> api.<Singular>
    - tf_field: SomeField
      sdk_field: SDKSomeField
      reason: "OpenAPI field name differs from the tfsdk tag"
  create_response: # create response: TF model -> api.<create_response_type>
    - tf_field: SomeField
      expression: types.StringValue(http.Name)
      reason: "create response nests the value differently"
  deserialize: # request body: TF model -> api.Create<Singular>JSONRequestBody
    - tf_field: LegacyField
      skip: true
      reason: "legacy field ignored by the new API"
  datasource: # datasource items: api.<Singular> -> ItemsValue
    []
  datasource_params: [] # datasource read filters: VmModel -> api.<ReadListParamsType> #   (separate from `datasource`: a TF attribute can map
    #    differently as a read filter vs a serialized item)

# Only needed when the inferred TF ObjectValuable type is wrong.
nested_type_overrides:
  - tf_field: InboundRules
    type_name: InboundRulesValue
```

Rules:

- `tags` is handled by the template pattern and is never auto-mapped.
- `sdk_field` forces the TF field to map to a differently-named SDK field.
- `expression` replaces the generated expression entirely (advanced).
- `skip` omits the field from the generated mapping.
- `nested_type_overrides` overrides the generated TF Value type for nested objects (default is `<TF field name>Value`).
- `reason` is required on every override so exceptions are documented.

#### Core signature inference

If `internal/core/<name>.go` already exists, `cmd/scaffold` parses it to discover the actual `Create<Name>`, `Read<Name>`, `Read<Plural>*`, `Delete<Name>`, and `Update<Name>Tags` signatures. Descriptor `core.*` values are only used when the parser cannot infer something, so hand-written core orchestration is preserved by default.

For special cases, you can override the inferred names:

```yaml
core:
  key_expr: state.Name.ValueString() # Go expr used as the key for core Read/Delete + tag-update (default state.Id.ValueString()). For name-keyed resources.
  create:
    extra_args: [vpcId] # Additional core.Create args beyond (ctx, provider, body)
    no_request_body: true # Create API takes no JSON body; emits no deserializer, Create passes only extra_args + tags
  read:
    function_name: ReadDHCPOption # Override the expected singular read function name
  read_list:
    function_prefix: PublicIP # Override the prefix used for core names
    function_suffix: WithParams # Suffix of the list function (e.g. "ReadVPCsWithParams")
    params_type: ReadVpcsParams # Type passed to the list function
  delete:
    extra_args: [vpcId]
  update:
    # Non-tag attribute updates. Each call is emitted in the generated Update,
    # gated on its when_changed fields, and passes args as literal Go expressions
    # after (ctx, r.Provider). `plan` and `state` are in scope; helpers can live
    # in a hand-written helpers.go in the same package. Tag reconciliation
    # (has_tags) is emitted automatically and separately.
    calls:
      - function_name: UpdateSubnetAttributes
        when_changed: [MapPublicIpOnLaunch] # fires when any listed field differs plan vs state
        args:
          - state.Id.ValueString()
          - plan.MapPublicIpOnLaunch.ValueBool()
```

The Update method runs the attribute calls first (each in its own `if changed`
block), then tag reconciliation, then a single `serialize`. Because Terraform
only invokes Update when the plan differs from state, the union of all
`when_changed` fields plus tags must cover every non-`ForceNew` attribute, or the
serialized object will be nil. Inputs that are passed as args but are not part of
the create body belong in `exclude_from_request`; server-computed read-only fields
belong in `computed_fields`.

##### Name-keyed resources (`core.key_expr` + `no_import`)

By default the generated Read/Delete (and the tag-update id) key the resource on
`state.Id.ValueString()`. For a resource the API addresses by name (or any other
attribute), set `core.key_expr` to the Go expression that yields the key, e.g.
`state.Name.ValueString()` — the `state` variable is in scope at all three call
sites. The Update method keeps using whatever you pass in `core.update.calls`
args (typically `plan.Name.ValueString()` for the post-rename name).

`BaseResource.ImportState` passes the import id through to the `id` attribute,
which is meaningless when the resource is keyed on something else. Set top-level
`no_import: true` to override `ImportState` with an explicit "not supported"
error instead of a silently broken id-passthrough.

> Caveat: `key_expr` does not change Terraform's update semantics. If a mutable,
> non-`ForceNew` attribute is write-only (never returned by the API and not
> updatable in place — e.g. server-certificate material), changing it in place
> either nil-serializes the Update or silently diverges state from the server.
> Mark those attributes `RequiresReplace` so a change recreates the resource. See
> "RequiresReplace (ForceNew)" below — declare them in the descriptor's
> `requires_replace:` and `cmd/inject-schema-overrides` re-applies the plan modifier
> on every `generate-spec`. (`server_certificate` graduated using `key_expr` + this.)

### Step 3 — Edit spec YAML

This file tells `tfplugingen-openapi` which OAS endpoints to map. It filters the full OAS down to the endpoints relevant for this feature.

#### Resource + data source

```yaml
provider:
  name: numspot

resources:
  organisation_role:
    create:
      method: POST
      path: /iam/organisations/{organisationId}/roles
    delete:
      method: DELETE
      path: /iam/organisations/{organisationId}/roles/{roleUuid}
    read:
      method: GET
      path: /iam/organisations/{organisationId}/roles/{roleUuid}
    schema:
      ignores:
        - organisationId

data_sources:
  organisation_role:
    read:
      method: GET
      path: /iam/organisations/{organisationId}/roles
    schema:
      ignores:
        - organisationId
```

#### Data source only

```yaml
provider:
  name: numspot

data_sources:
  organisations:
    read:
      method: GET
      path: /iam/organisations
    schema:
      ignores: []
```

#### Rules

- Path parameters like `{spaceId}` or `{organisationId}` must be listed in `schema.ignores` — they're provided by the provider config, not by the TF resource
- The key under `resources:` / `data_sources:` must match `name` from the descriptor
- For Object Storage features, use `make generate-os-spec` instead of `make generate-spec`

### Step 4 — Generate TF schemas (\_gen.go files)

```bash
make generate-spec RESOURCE_NAME=organisation_role
make generate-framework RESOURCE_NAME=organisation_role
```

This produces:

```
internal/services/organisation_role/
├── organisation_role_spec.json                         ← from generate-spec
├── resource_organisation_role/
│   └── organisation_role_resource_gen.go               ← from generate-framework
│       → OrganisationRoleResourceSchema(ctx) schema.Schema
│       → OrganisationRoleModel struct
└── datasource_organisation_role/
    └── organisation_role_data_source_gen.go            ← from generate-framework
        → OrganisationRoleDataSourceSchema(ctx) schema.Schema
        → OrganisationRoleModel struct
        → ItemsType / ItemsValue (custom types for nested list)
```

These files are marked `DO NOT EDIT` — they contain only schema definitions and model types. The next step generates the code that **uses** them.

#### RequiresReplace (ForceNew) and other plan modifiers

`tfplugingen-openapi` does not emit plan modifiers, so they would be lost every
time the IR is regenerated. Instead of hand-editing the committed `*_spec.json`,
declare the attributes in the **descriptor** and let `cmd/inject-schema-overrides`
re-apply them automatically. `make generate-spec` runs this post-processor right
after the openapi step (mirroring `cmd/inject-ignores`), so the modifiers survive
regeneration and the descriptor stays the single source of truth:

```yaml
# descriptor.yaml — snake_case schema attribute names
requires_replace: [body, private_key, chain]
```

On `make generate-spec` this injects a `RequiresReplace()` `custom` plan modifier
for each listed top-level attribute (the tool picks the right `*planmodifier`
subpackage from the attribute type), producing in `<name>_spec.json`:

```json
{
  "name": "private_key",
  "string": {
    "computed_optional_required": "required",
    "plan_modifiers": [
      {
        "custom": {
          "imports": [
            {
              "path": "github.com/hashicorp/terraform-plugin-framework/resource/schema/planmodifier"
            },
            {
              "path": "github.com/hashicorp/terraform-plugin-framework/resource/schema/stringplanmodifier"
            }
          ],
          "schema_definition": "stringplanmodifier.RequiresReplace()"
        }
      }
    ]
  }
}
```

`make generate-framework` then renders these into `*_gen.go`. The injector is
idempotent and round-trips through the same `terraform-plugin-codegen-spec` types
that `tfplugingen-openapi` uses, so it only adds the modifiers — no key reordering
or other diff churn. It fails loudly if a declared name has no matching top-level
attribute (typo guard).

`requires_replace: [...]` is shorthand for the common case. For everything else —
other modifier kinds, nested attributes, or a predicate — use the structured
`plan_modifiers:` list. Each entry targets an attribute by dotted **Path**
(snake_case segments; each segment after the first descends into the nested
object's attributes) and a **Kind**:

```yaml
plan_modifiers:
  - path: ip_range # top-level
    kind: requires_replace_if_configured
  - path: link_nic.vm_id # nested (a list/set/single nested object)
    kind: use_state_for_unknown
  - path: link_nic.vm_id # an attribute may carry several modifiers
    kind: requires_replace_if_configured
  - path: size
    kind: requires_replace_if # predicate form
    func: ReplaceVolumeSize # package-local func in resource_<name>/
    description: "Replaced when the new size is smaller and downsize is allowed."
    # description_markdown: optional, defaults to description
```

Supported `kind` values (the tool derives the `*planmodifier` subpackage from the
attribute type, so the same kind works for string/bool/int64/list/set/etc.):

| kind                             | emits                                                   |
| -------------------------------- | ------------------------------------------------------- |
| `requires_replace`               | `<sub>.RequiresReplace()`                               |
| `requires_replace_if_configured` | `<sub>.RequiresReplaceIfConfigured()`                   |
| `use_state_for_unknown`          | `<sub>.UseStateForUnknown()`                            |
| `requires_replace_if`            | `<sub>.RequiresReplaceIf(<func>, "<desc>", "<descMd>")` |

`requires_replace` is the correct home for immutable, write-only inputs (e.g.
certificate material) that have no in-place API update — combine it with
`key_expr` / `update.calls` for the mutable fields. (Note `make generate-spec`
takes `RESOURCE_NAME` matching the spec file prefix, e.g. `servercertificate`.)

#### Non-OAS validators and static defaults

Most validators (`LengthAtMost`, `RegexMatches`, `OneOf`, `Between`…) and many
`static` defaults are derived by `tfplugingen-openapi` from the OAS and survive
regeneration — **do not** declare those. Only the ones the OAS does _not_ produce
(e.g. `stringvalidator.ConflictsWith`, or provider-side defaults) need declaring;
`cmd/inject-schema-overrides` re-applies them too. Validators are **appended** to
the OAS-derived set (deduped by `schema_definition`); defaults are **set** by the
attribute's type. Both accept the same dotted `path:` as `plan_modifiers`.

```yaml
# Non-OAS custom validators — declare the full Go expression + its imports.
validators:
  - path: nic_id
    schema_definition: 'stringvalidator.ConflictsWith(path.MatchRoot("vm_id"))'
    imports:
      - github.com/hashicorp/terraform-plugin-framework-validators/stringvalidator
      - github.com/hashicorp/terraform-plugin-framework/path

# Non-OAS static defaults — the value is typed against the attribute (bool/int64/string/...).
defaults:
  - path: size
    static: 10
  - path: type
    static: standard
```

`clear_defaults:` is the **inverse** of `defaults:`. Occasionally the OAS attaches a
default to an attribute the provider must keep default-free (e.g. a read-only mirror
field that duplicates a writable input — `vm.vm_initiated_shutdown_behavior`). List
its dotted `path:` and the injector drops the OAS-emitted default after `defaults:`
runs (so a path is never both set and cleared). It works on bool/string/int64/float64
leaves.

```yaml
clear_defaults:
  - vm_initiated_shutdown_behavior
```

> `public_ip`/`internet_gateway` are create-without-body, so the mapper emits no
> resource schema; their resource IR is now **synthesized from the datasource
> `items` element** (see "Create-without-body synthesis" below) and regenerates
> normally. Provider-side attributes that are simply _absent_ from the OAS (e.g.
> `volume.replace_volume_on_downsize`) are re-added by `synthetic_attributes:`
> (below).

#### Set-typing and optionality

`tfplugingen-openapi` emits every array as an ordered **list** and marks
read-derived fields **computed**. Order-insensitive API collections (ids, ips,
rules) must be **sets**, otherwise Terraform shows a phantom diff whenever the API
returns the elements in a different order. `cmd/inject-schema-overrides` fixes
both, descriptor-driven, so the committed `*_spec.json` stays reproducible:

```yaml
# Convert list / list_nested attributes to set / set_nested (dotted paths).
sets:
  - security_group_ids
  - routes

# Override computed_optional_required when the attribute is user-settable
# (openapi often derives `computed` from the read schema).
optionality:
  - path: dhcp_options_set_id
    value: computed_optional # computed | computed_optional | optional | required
```

`tags` is the universal case (set_nested, `computed_optional`, with `required`
key/value). It is applied **automatically** for every `has_tags: true` resource —
do **not** declare it under `sets:`/`optionality:`. Conversion runs before plan
modifiers/validators so they see the final set type. A resource that _has_ tags
must set `has_tags: true` even if its CRUD is hand-written, so the IR normalizes
them consistently (e.g. `image`).

#### Synthetic attributes (provider-only, absent from the OAS)

Some attributes exist only provider-side and have no OAS field, so the mapper
drops them and `make generate-spec` cannot reproduce them: inline-managed inputs
(`route_table.subnet_id`/`subnet_ids`), serialize-derived blocks
(`virtual_gateway.vpc_id`, `volume.link_vm`, `route_table.local_route`) and
write-only flags (`volume.replace_volume_on_downsize`). Declare them under
`synthetic_attributes:` and `cmd/inject-schema-overrides` re-adds them
(resource-side only) **before** every other pass, so `sets:`/`optionality:`/
`plan_modifiers:`/`validators:`/`defaults:` can target them as usual.

```yaml
synthetic_attributes:
  - path: vpc_id # dotted path; the leaf is added under its parent
    type: string # string|bool|int64|float64|number|list|single_nested
    value: computed_optional # computed_optional_required
    description: "..." # provider-owned (the attr is not in the OAS at all)
  - path: subnet_ids
    type: list
    element_type: string # required for list
    value: computed_optional
  - path: local_route # nested blocks list their children recursively
    type: single_nested
    value: computed
    attributes:
      - path: gateway_id
        type: string
        value: computed_optional
        description: "..."
```

Declare only the **structure** here (type, optionality, description,
`deprecation_message`, `element_type`, nested `attributes`). The default / plan
modifier / validator come from the existing `defaults:`/`plan_modifiers:`/
`validators:` blocks (they run afterwards). Synthetic attrs are appended in
declaration order; the first regen rewrites the committed `*_spec.json` and that
becomes the drift baseline. This is the **one** place a description lives outside
the OAS — because the attribute is not in the OAS — and it does not reintroduce a
general `descriptions:` knob.

#### Create-without-body synthesis (`core.create.no_request_body`)

Some resources are created with an empty body and configured via follow-up link
calls (e.g. `internet_gateway`, `public_ip`); they set `core.create.no_request_body:
true`. `tfplugingen-openapi` then maps **no** resource schema at all, so the IR
used to be hand-maintained. `cmd/inject-schema-overrides` now **synthesizes the
resource schema from the datasource `items` element** (the per-instance read view)
when the resource is missing and `no_request_body` is set — a recursive
`datasource.Attribute -> resource.Attribute` conversion. Every synthesized
attribute starts `computed` (the read schema is read-only); the usual
`optionality:`/`plan_modifiers:`/`validators:`/`defaults:` blocks and `has_tags`
normalization then mark the user-settable ones (e.g. `vpc_id`, `vm_id`, `nic_id`)
and add their behavior. Nothing extra to declare beyond `no_request_body: true`
plus those overrides; the first regen rewrites the committed `*_spec.json` (the
attribute order follows `items`). Datasource-only item validators are dropped (the
resource's are declared via `validators:`).

#### Renames (collision-avoiding leaf renames)

The OAS reuses one schema name in several nesting contexts (e.g. `link_public_ip`
appears both at NIC level and under `private_ips`; `security_groups` appears both
top-level and under `nics`). `tfplugingen-framework` emits one Go type per
distinct attribute name, so two same-named nested objects **collide**. Rename the
nested occurrences to unique names with `renames:`; the leaf **type** is untouched,
only the name changes, and the rename is applied to the resource at `path` **and**
to the datasource at `items.` + `path` (the two must stay consistent so the
framework generates both sides). Renames run **before** every other pass so later
passes can target the final names.

```yaml
renames:
  - path: private_ips.link_public_ip # resource path (datasource: items.<path>)
    to: link_public_ip_private_ip
  - path: nics.security_groups
    to: nic_security_groups
```

`cmd/scaffold` is **rename-aware**: a renamed nested leaf (e.g.
`link_public_ip_private_ip`) no longer matches its SDK field by name, so the
serialize generator reverses the rename (recovering the original OAS leaf,
`link_public_ip` → SDK `LinkPublicIp`) when matching nested fields. This means a
renamed nested object still auto-maps with no `mapping_overrides`. (The SDK struct
keeps the OAS name; only the TF attribute is renamed.)

#### Descriptions: the OAS is the source of truth

There is deliberately **no** `descriptions:` override knob. Attribute descriptions
always come from the OAS via `tfplugingen-openapi`; if the wording is wrong, fix it
**upstream in the OAS** (its owners) and regeneration picks it up. This keeps the
provider docs in lockstep with the API and avoids a large hand-maintained surface.
More broadly: prefer conforming the **source/input** (OAS, `*_spec.yaml`,
`descriptor.yaml`) to a standard pattern over adding bespoke logic to the
generator / scaffold / injector. `inject-schema-overrides` only re-applies what the
mapper provably cannot derive (plan modifiers, set-typing, optionality, non-OAS
validators/defaults) — it is intentionally **resource-side only** and gains no
special cases to paper over individual resources. A resource that cannot be made
reproducible without a generator feature or a behavior/schema change is left in the
backlog rather than worked around.

#### spec.json drift gate (`spec_check`)

Once a resource's `*_spec.json` is byte-reproducible from `make generate-spec`
(verify with the regenerate-and-diff in `cmd/scaffold drift`), set
`spec_check: true` in its descriptor. `make check-scaffold-drift` then regenerates
the IR through the full pipeline (`inject-ignores` -> `tfplugingen-openapi` ->
`inject-schema-overrides`) and fails on any drift — so hand-edits to a generated
`*_spec.json` can no longer slip in unnoticed. It is independent of
`scaffold_check` (which guards the orchestration `.go`), so coverage can be
ratcheted up one resource at a time.

#### Spec file naming

Every `*_spec.json` / `*_spec.yaml` must be named `<folder>_spec.<ext>` (prefix ==
the service folder), because `generate-spec` / `generate-framework` derive the path
from `RESOURCE_NAME` (the folder) and `inject-schema-overrides` runs off that path.
An irregular prefix silently skips the file from regeneration. `cmd/scaffold audit`
enforces this as a hard error.

> Tip: when a resource's `read` reuses a **list** endpoint, the IR pulls the
> list-wrapper fields (e.g. `items`, `paths`) into the resource schema. Those
> belong to the data source, so add them to the resource's `schema.ignores` in
> `<name>_spec.yaml` (see `server_certificate`).

### Step 5 — Generate business logic

```bash
make scaffold RESOURCE_NAME=organisation_role
```

This produces 3 files + patches `provider.go`:

```
internal/core/organisation_role.go                      ← Create/Read/ReadList/Delete
internal/services/organisation_role/resource_organisation_role.go   ← CRUD + serialize/deserialize
internal/services/organisation_role/datasource_organisation_roles.go ← Read + mappingItemsValue
internal/provider/provider.go                           ← auto-patched (import + registration)
```

`cmd/scaffold` will:

- Infer core function names/signatures from an existing `internal/core/organisation_role.go` if present, or fall back to the descriptor `core.*` config.
- Auto-fill simple field mappings (strings, ints, bools, lists/sets, single nested objects, and nested collections).
- Emit `TODO` comments only for fields it cannot map automatically.

#### What the serialize/deserialize generator covers

The field mapper ([cmd/scaffold/type_mapper.go](../../cmd/scaffold/type_mapper.go)) resolves
most fields without any override:

- **Recursive nested objects (any depth).** Nested serializers thread a shared
  accumulator, so an object nested inside another object (e.g. `vpn_options →
phase1options/phase2options`) generates its own sub-serializers instead of
  being silently dropped. Each level rewrites its expressions against its own
  local parameters, and duplicate sub-serializers are de-duplicated.
- **Case/separator-insensitive SDK field matching.** When the exact
  `snakeToPascal(tag)` lookup misses (a snake tag that lost a word boundary, e.g.
  `phase1options` → SDK `Phase1Options`), the mapper falls back to a normalized
  match (lowercased, separators stripped). The fallback is skipped if it would be
  ambiguous within a struct, so it never guesses.
- **Value vs pointer type pairs.** In addition to the pointer forms, the mapper
  handles value `Uuid → types.String` (SDK fields written with the `Uuid` alias,
  e.g. `VPNConnection.ClientGatewayId`) and value `time.Time → types.String`
  (e.g. `VgwTelemetry.LastStateChangeDate`). Value-time uses
  `utils.TimeToTfString` / `utils.TfStringToTime`.
- **Correctly-cased create-body type.** The create request body resolves to the
  real SDK struct name (e.g. `api.CreateVPNConnectionJSONRequestBody`, not the
  descriptor's `Vpn` casing).

A nested object that is read-only (present in the read response but absent from
the create body) still gets a generated deserializer; it is dead code (the
create deserializer skips fields listed in `computed_fields` /
`exclude_from_request`). This matches the existing scaffold baseline — `unparam`
on an unused `ctx` and `unused` on those deserializers are expected on generated
files and are not new findings.

### Step 6 — Review TODOs and add overrides

The generator auto-fills simple field mappings (for example, `types.String` ↔ `*string`). Any unsupported or mismatched field is left as a `TODO` comment. Search for `TODO` in the generated files and either:

- Add a `mapping_overrides` entry to `descriptor.yaml` and rerun `make scaffold`, or
- Edit the generated file directly if the case is one-off.

#### `resource_<name>.go` — 3 functions to fill

```go
func serializeOrganisationRole(http *api.OrganisationRole) resource_organisation_role.OrganisationRoleModel {
    return resource_organisation_role.OrganisationRoleModel{
        Id:          types.StringPointerValue(http.Id),
        Name:        types.StringPointerValue(http.Name),
        Description: types.StringPointerValue(http.Description),
    }
}

func deserializeCreateOrganisationRoleRequest(tf resource_organisation_role.OrganisationRoleModel) api.CreateOrganisationRoleJSONRequestBody {
    return api.CreateOrganisationRoleJSONRequestBody{
        Name:        tf.Name.ValueString(),
        Description: tf.Description.ValueStringPointer(),
    }
}
```

For resources with tags, `serialize` also takes `ctx` + `diags`, and includes tags mapping.

#### `datasource_<name>s.go` — 1-2 functions to fill

```go
func mappingItemsValue(ctx context.Context, item api.OrganisationRole) (datasource_organisation_role.ItemsValue, diag.Diagnostics) {
    return datasource_organisation_role.NewItemsValue(
        datasource_organisation_role.ItemsValue{}.AttributeTypes(ctx),
        map[string]attr.Value{
            "id":          types.StringValue(utils.ConvertStringPtrToString(item.Id)),
            "name":        types.StringValue(utils.ConvertStringPtrToString(item.Name)),
            "description": types.StringValue(utils.ConvertStringPtrToString(item.Description)),
        },
    )
}
```

For datasources with tags, also fill `mappingTags()`.

#### `core/<name>.go` — usually no TODOs

Core functions are fully generated from the descriptor flags. Only edit if you need custom API call patterns.

#### Helper: finding field names

- **API model fields**: look at the struct `api.OrganisationRole` in `internal/sdk/api/numspot-client.go`
- **TF model fields**: look at `OrganisationRoleModel` in the `_gen.go` file
- **SDK method names**: look at `CreateOrganisationRoleWithResponse`, `ReadOrganisationRolesByIdWithResponse`, etc. in `internal/sdk/api/numspot-client.go`

### Step 7b — Enable scaffold drift guard (optional)

Once you are happy with the generated files and intend to keep them in sync with the descriptor, enable the guard:

```yaml
scaffold_check: true
```

Run the checks locally before pushing:

```bash
go run ./cmd/scaffold audit
go run ./cmd/scaffold drift
```

When `scaffold_check` is `true`:

- `cmd/scaffold drift` fails if the committed files differ from `cmd/scaffold gen -dry-run`, and
- `cmd/scaffold audit` fails if generation produces **any** residual `TODO` (i.e. a field that could
  not be auto-mapped). A resource opted into the guard must map every field. If a field genuinely
  cannot be auto-mapped, either add a pattern flag / mapping override, or keep `scaffold_check: false`
  with a `reason` and maintain the file by hand.

This prevents the false-confidence case where a "checked" resource silently ships `TODO` placeholders.

If you keep `scaffold_check: false` (or omit it), you must provide a `reason`:

```yaml
scaffold_check: false
reason: "custom VM association logic not yet expressible in the generator"
```

`cmd/scaffold audit` enforces this rule and also requires a `reason` on every `mapping_overrides` entry.

### Step 8 — Register the resource

Every new resource must be declared in the internal registry so that the retry/async reference table stays up to date.

1. Open `docs/internal/resources-registry.yaml`.
2. Add an entry for the new resource under the correct category and owner team.
3. Fill in the `operations` block (async, polling states, retry pattern, timeout).
4. Run:

```bash
make generate-resource-registry
```

This regenerates three files from the YAML source of truth: `docs/internal/RESOURCE_REGISTRY.md`, the
root `OWNERS.md` (human-readable team -> resources map), and `.github/CODEOWNERS` (functional GitHub
path -> team mapping used to auto-assign reviewers). Setting `owner_team` correctly on the new entry is
what drives ownership in both `OWNERS.md` and `.github/CODEOWNERS`.

> The GitHub team handles in `.github/CODEOWNERS` (e.g. `@numspot/numspot-iaas`) are defined in
> `cmd/resource-registry/main.go` (`teamHandles`). GitHub requires the referenced teams to exist in the
> org and have explicit write access to the repository — otherwise the line is silently skipped (no
> owner assigned). CI (`make check-registry-drift`, run by the GitHub Actions CI workflow) fails if
> these generated files are not regenerated and committed.

### About `cmd/resource-registry/`

`make generate-resource-registry` runs the small Go program in `cmd/resource-registry/main.go`.

Purpose:

- Read `docs/internal/resources-registry.yaml`, the source of truth for async/retry metadata and `owner_team`.
- Produce a sorted Markdown table in `docs/internal/RESOURCE_REGISTRY.md`.
- Produce the root `OWNERS.md` and the functional `.github/CODEOWNERS` from `owner_team`.

Usage:

```bash
make generate-resource-registry
# equivalent to:
go run ./cmd/resource-registry
```

Behavior:

- Resources are grouped by console category and sorted alphabetically within each category.
- The previous `RESOURCE_REGISTRY.md` is backed up to `RESOURCE_REGISTRY.md.bak` and then removed.
- Generated file must not be edited by hand; always edit the YAML registry and rerun the command.

## Scope: space vs organisation

| Scope          | Provider field            | URL pattern                                  | Examples                                       |
| -------------- | ------------------------- | -------------------------------------------- | ---------------------------------------------- |
| `space`        | `provider.SpaceID`        | `/compute/spaces/{spaceId}/...`              | VPC, Subnet, Keypair, SecurityGroup            |
| `space`        | `provider.SpaceID`        | `/iam/spaces/{spaceId}/...`                  | Space-scoped Roles, Permissions, ACL           |
| `organisation` | `provider.OrganisationID` | `/iam/organisations/{organisationId}/...`    | Org Roles, Permissions, ServiceAccounts, Users |
| `organisation` | `provider.OrganisationID` | `/organisations/{organisationId}/spaces/...` | Space management                               |

The descriptor `scope` field controls which provider field the generated code uses. `organisation_id` is optional in the provider schema — organisation-scoped resources validate its presence at runtime.

## Generation coverage and the generated / hand-written boundary

The generator follows a **skeleton-first** policy. It reliably produces:

- the full CRUD skeleton (resource, datasource, core wiring, provider registration), and
- the obvious field mappings (scalars, strings/ints/bools, simple lists/sets, single nested objects,
  and tags via the template pattern).

It does **not** try to be lossless for every resource. A resource is only allowed to set
`scaffold_check: true` when generation maps **every** field with no residual `TODO` (enforced by
`cmd/scaffold audit`). Anything with custom orchestration, derived fields, non-string IDs, or
nested shapes the mapper does not support stays hand-written with `scaffold_check: false` and a
`reason`.

The authoritative coverage list is the audit itself — there is no static table to keep in sync:

```bash
make audit              # lists every descriptor; fails on unresolved mappings / convention breaks
make check-scaffold-drift
```

At the time of writing, **26 of 28** resources are genuinely generated (drift-guarded, TODO-free)
and their `*_spec.json` is byte-reproducible (`spec_check`); see
[`SCAFFOLD_GRADUATION_LOG.md`](SCAFFOLD_GRADUATION_LOG.md) for the authoritative, up-to-date list and
the recipes used to graduate the hard cases. Both ratchets have reached the in-scope ceiling — the
only two resources below the line are out of scope:

| Reason category                                                 | Examples          |
| --------------------------------------------------------------- | ----------------- |
| Standby — not registered in the provider, OAS path absent       | openshift_cluster |
| Separate `objectstorage` SDK / schema composition not supported | bucket            |

The mapper auto-maps scalars, string/int lists & sets, single nested objects, **and lists/sets of
nested objects** (it generates the per-element `serialize…`/`deserialize…`/`mapping…` helpers using
the framework's `<Field>Value` element types). The historically hard cases (derived fields like
nat_gateway's `PublicIpId`, non-string IDs, parent-scoped sub-resources, bespoke cluster surfaces)
were graduated by conforming the hand-written core to the generator's expected shape and/or adding a
declarative descriptor knob, rather than teaching the generator exotic behavior — see the recipes
(A–H) in the graduation log.

When a new resource cannot yet be made TODO-free, keep `scaffold_check: false` with a `reason`,
maintain the file by hand, and let `make audit` track it.

## Command summary

The full list of `make` targets and `cmd/scaffold` subcommands lives in
[COMMANDS.md](COMMANDS.md). The generation targets you need here:

| Command                                   | What it does                                                 |
| ----------------------------------------- | ------------------------------------------------------------ |
| `make scaffold-init RESOURCE_NAME=x`      | Creates directory + `descriptor.yaml` + `<name>_spec.yaml`   |

| `make generate-framework RESOURCE_NAME=x` | Generates `_gen.go` files (schema + models)                  |
| `make scaffold RESOURCE_NAME=x`           | Generates core + resource + datasource + patches provider.go |

```bash
make scaffold-init RESOURCE_NAME=organisation_role

make generate-spec RESOURCE_NAME=organisation_role
make generate-framework RESOURCE_NAME=organisation_role
make scaffold RESOURCE_NAME=organisation_role
# fill in TODOs
make fmt && go build ./...
```
